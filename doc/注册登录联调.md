# 注册与登录接口联调

## 本地依赖

启动 MySQL 和 Redis。数据库已经执行 Flyway V1～V6。后端默认连接 `localhost:6379`，可通过 `REDIS_HOST`、`REDIS_PORT` 修改；生产环境将 `SESSION_COOKIE_SECURE=true` 并使用 HTTPS。前端开发地址当前允许 `http://localhost:5173`，上线前要配置为实际域名。

## Postman 顺序

1. `GET http://localhost:8080/api/auth/csrf`。保存响应 Cookie，并取得 JSON 中的 `headerName` 和 `token`。
2. 对注册、登录、退出这些 POST 请求，发送同一 Cookie，并加请求头 `X-XSRF-TOKEN: <上一步的 token>`。
3. 注册：`POST /api/auth/register`，JSON `{"email":"you@example.com","password":"至少8位密码"}`。成功返回 `id`、`email`；同邮箱重复注册返回 409。
4. 登录：`POST /api/auth/login`，使用同样的 JSON；成功后服务器返回 Session Cookie。密码错误返回 401，连续失败 5 次锁定约 15 分钟。
5. 当前用户：`GET /api/auth/me`，带 Session Cookie；成功返回用户 ID 和邮箱，未登录返回 401。
6. 退出：`POST /api/auth/logout`，带 Session Cookie 和 CSRF 请求头；成功返回 204。之后再次调用 `/me` 应返回 401。

登录后如 CSRF Cookie 或 token 发生变化，重新调用 `GET /api/auth/csrf` 获取新 token。浏览器前端请求需要带 `credentials: 'include'`。密码只在请求体中传输，必须在 HTTPS 环境使用；数据库只保存 BCrypt 哈希。

## 当前范围

本次只完成邮箱密码注册、登录、退出、当前用户查询和 Redis Session。邮箱验证、找回密码、删除账号及分布式登录限流是后续独立接口；`verification_codes` 等表已预留。当前失败锁定逻辑是数据库计数，生产发布前还需增加 IP/账号维度的 Redis 限流，并配置监控与告警。
