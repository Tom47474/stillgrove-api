# Stillgrove 本地建表步骤

后端项目路径：`/Users/shibin/workspace/stillgrove/stillgrove-api`。`pom.xml` 已包含 MyBatis Spring Boot Starter、Spring Boot Flyway Starter、`flyway-mysql` 和 MySQL Connector/J；本地配置已启用 Flyway，迁移目录为 `classpath:db/migration`。业务 SQL 位于 MyBatis Mapper XML，Flyway 负责建表。

## 1. 确认 MySQL 版本并创建空库

在终端执行：

```bash
mysql --version
mysql -u root -p
```

进入 MySQL 后执行：

```sql
CREATE DATABASE IF NOT EXISTS stillgrove
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

SHOW DATABASES LIKE 'stillgrove';
EXIT;
```

迁移 SQL 假定 MySQL 8.0+。数据库只需先创建一次，**业务表交给 Flyway 创建**。如果库里已有手工创建的业务表，先备份并核对现状，不要直接运行这些初始迁移。

## 2. 配置数据库连接

后端本地配置文件为 `src/main/resources/application-local.yaml`。确认 `spring.datasource.url` 指向 `stillgrove`，账号和密码是你本机 MySQL 的实际值。当前项目的连接 URL 使用 `Asia/Shanghai`；本设计统一用 UTC 存储时间，因此在开始写入业务数据前，应将连接时区和应用时间处理一起改为 UTC。建议把密码改为环境变量，避免提交到 Git：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/stillgrove?connectionTimeZone=UTC
    username: ${DB_USERNAME:root}
    password: ${DB_PASSWORD}
    driver-class-name: com.mysql.cj.jdbc.Driver
  flyway:
    enabled: true
    locations: classpath:db/migration
```

上面是需要保留的关键配置，不要求直接覆盖已有文件的其他配置。若使用环境变量，启动 IDEA 前在运行配置的 Environment variables 中设置 `DB_PASSWORD`（也可设置 `DB_USERNAME`）。不要把真实密码写进文档或提交到仓库。

## 4. 启动应用并检查

在 IDEA 中运行 `StillgroveApiApplication`。启动时 Flyway 会按版本顺序执行 `V1` 到 `V6`。看到应用成功启动后，执行：

```bash
mysql -u root -p stillgrove
```

```sql
SHOW TABLES;
SELECT installed_rank, version, description, success
FROM flyway_schema_history
ORDER BY installed_rank;
SHOW CREATE TABLE messages\G
```

应能看到 16 张业务表和 `flyway_schema_history`，且 6 条迁移记录的 `success` 均为 `1`。

## 5. 常见问题

- **连接失败**：检查 MySQL 是否运行、端口、数据库名、账号密码。
- **Flyway 校验失败**：不要修改已执行的 `V1`～`V6`；新增下一个版本迁移文件。若是本地试验库且确定无业务数据，可在备份后重建空库再运行。
- **MyBatis Mapper 找不到 SQL**：检查 `application.yaml` 的 `mybatis.mapper-locations`，以及 Mapper 接口的方法名与 XML 中的 `id` 是否一致。
- **启动成功但没表**：检查 Flyway 是否启用、`application-local.yaml` 是否生效、SQL 是否在 `src/main/resources/db/migration/`。
